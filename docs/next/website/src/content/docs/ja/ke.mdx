ke（壳、「殻」）は Herdr の改変版フォークです。Herdr のランタイム、ペイン、エージェント検出をそのまま保ち、コーディングエージェントの隣に住む常駐モデルのために 2 つのフックを追加します。

- フォーカス中のペインの下に出る**コンポーザーバー**。エージェントへ送るテキストは CLI に届く前にローカルのプロセッサー（マスキング、または `@ke` プロンプトを常駐モデルへ渡す処理）を通ります。
- ke コーディネーターが書き込む**サイドバーパネル**。各 CLI のクォータ、タスク、常駐モデルの状態がエージェント一覧の隣に表示され続けます。

プロセッサーとコーディネーターは別のプログラムで、ke はその接続方法だけを定義します。これらが無いときはコンポーザーはテキストをそのまま送り、パネルは隠れ、ke は Herdr と同じように動きます。

組み込みヘルプに `herdr <command>` と書かれている箇所は、`ke <command>` を実行してください。

## インストール

macOS と Linux（x86_64 / aarch64）:

```bash
curl -fsSL https://github.com/Little-Z7/ke/releases/latest/download/ke-install.sh | sh
```

スクリプトはリリースの `SHA256SUMS` を確認したうえで `~/.local/bin/ke` にインストールします（`KE_INSTALL_DIR` で変更可）。`KE_RELEASE_TAG=ke-v0.1.0` でバージョンを固定できます。更新はもう一度実行するだけです。`ke update` は意図的に拒否し、このコマンドを表示します。

ソースからビルドする場合はチェックアウト内で `scripts/ke-install.sh` を実行します（Rust と Zig 0.15.2 が必要）。`cargo install` は使わないでください。`herdr` という名前のバイナリができてしまいます。

## herdr との分離

ke は上流の Herdr がインストールされた同じマシンで、それに触れずに動きます。

- 設定、ソケット、セッション、ログ、プラグインは `herdr` ではなく `ke` アプリディレクトリ（デバッグビルドでは `ke-dev`）に置かれます。
- セルフアップデートと `ke integration install` / `uninstall` は無効です。ke は `herdr integration install <agent>` が各 CLI に入れたエージェント状態フックを再利用します。フックは `HERDR_SOCKET_PATH` でソケットを探し、ke のペインではこの変数が ke 自身のソケットを指します。フックが無い場合は画面ベースの状態検出にフォールバックします。
- ke が起動したペインには Herdr の `HERDR_ENV=1` に加えて `KE_ENV=1` が付きます。
- 上流 Herdr のペイン内から `ke` を起動した場合（`HERDR_ENV=1` があり `KE_ENV` が無い）、継承した `HERDR_*` ロケーター変数を先に削除します。そのため ke が Herdr のサーバーに接続したり、Herdr のネスト禁止ガードに引っかかることはありません。

## コンポーザーバー

`prefix+i`（`keys.toggle_composer` で変更可）でペイン面の下に 2 行のバーを開きます。開いている間、入力や貼り付けたテキストはフォーカス中のペインではなくバーに入ります。

- **Enter** はテキストをプロセッサーに渡し、その返答をフォーカス中のペインへ送ります。エージェントペインには `agent.prompt`、通常のターミナルには `pane.send_input` と Enter を使います。
- **Esc** または **Ctrl+U** でバーをクリア、**Backspace** で削除します。
- バーが**空**のときは Enter、Esc、Backspace はそのままペインに届くので、エージェント自身の確認や中断は引き続き機能します。
- ステータス行には対象ペインとプロセッサーの最新のメモが表示されます。送信処理中に入力したテキストは保持されます。

バーが勝手に送信することはありません。パネル行のクリック（後述）はバーにテキストを入れるだけで、Enter は自分で押します。

### プロセッサープロトコル

プロセッサーは Unix ソケットで待ち受けます。送信ごとに ke は接続し、JSON を 1 行書き、JSON を 1 行読み戻します。

```json
{"pane_id":"wA:p2","agent":"claude","text":"deploy with key sk-live-..."}
```

```json
{"action":"send","text":"deploy with key [REDACTED]","note":"1 secret masked"}
```

| `action` | 効果 |
| --- | --- |
| `send` | `text`（無い場合は元のテキスト）をペインへ送り、`note` をステータス行に表示します。 |
| `block` | 何も送らず、テキストをバーに残し、`note` を表示します。 |
| `done` | 何も送らず、バーをクリアします。プロセッサーが入力を自分で引き受けました（例: `@ke ...` を常駐モデルへ渡した）。 |

それ以外の返答、不正な JSON、接続エラー、5 秒以内に返答が無い場合はすべて `block` として扱います。プロセッサーはゲートです。いちど設定されたら、その失敗によってテキストが通り抜けることはありません。プロセッサーがまったく設定されていないときは、テキストはそのまま送られます。

30 ms より速い返答はキーハンドラー内で完了し、遅いものはメインループのタイマーで完了するため、UI がソケットでブロックされることはありません。

## サイドバーパネル

コーディネーターが動いていると、エージェントセクションの下部にタイトル行と最大 12 行のパネルが表示されます。各行には色レベルがあります: `ok`、`warn`、`err`、`info`（既定）、`dim`。

- `input` を持つ行には下線が付きます。クリックするとコンポーザーバーが開き、そのテキストが入ります。Enter を押すまで何も送られないので、コーディネーターは `@ke 继续` のような、プロセッサーを通るアクションを提示できます。
- ファイルが 30 秒以上更新されていないとタイトルに `· offline` が付き、行が暗くなります。10 分を超えるとパネルは消えます。
- パネルはエージェント行を最低 4 行残し、エージェントセクションの半分を超えて占有することはありません。

### パネルファイル

コーディネーターは 1 つの JSON ファイルを書きます。ke は 2 秒ごとに更新時刻を確認し、変化したときだけ読み直します。64 KiB を超えるファイルは無視されます。

```json
{
  "v": 1,
  "ts": 1726200000.0,
  "title": "ke",
  "rows": [
    {"text": "claude ok 5h 34%", "level": "ok"},
    {"text": "codex limited", "level": "warn"},
    {"text": "继续上一个任务", "level": "info", "input": "@ke 继续"}
  ]
}
```

`ts`（Unix 秒、必須）は書き込み時刻で、offline と非表示の判定に使われます。`title`、`text`、`input` の制御文字は除去または置換されます。`title` は 40 文字、`text` は 120 文字、`input` は 2000 文字で切られます。`text` の無い行は捨てられます。

## 設定

2 つのパスは既定で `~/.workcat/ke/` にあります。プロセスを別の場所に置く場合は `config.toml` で設定します。環境変数は設定ファイルより優先されます。

```toml
[ke]
# コンポーザープロセッサーの Unix ソケット。設定すると、プロセッサーの失敗は送信をブロックします。
# 未設定: ~/.workcat/ke/composer.sock が存在する間はそれを使い、無ければテキストをそのまま送ります。
composer_socket = "~/.workcat/ke/composer.sock"
# コーディネーターが書く panel.json。
panel_file = "~/.workcat/ke/panel.json"
```

| キー | 上書きする環境変数 |
| --- | --- |
| `ke.composer_socket` | `KE_COMPOSER_SOCKET` |
| `ke.panel_file` | `KE_PANEL_FILE`、次に `WORKCAT_KE_HOME`（`<dir>/panel.json` を使用） |

`[ke]` の変更は次回の設定リロードで反映されます。コンポーザーのソケットは送信ごとに解決されるので、ke の起動後に立ち上げたプロセッサーも自動的に使われます。`keys.toggle_composer` は他のキーバインドとともに[設定リファレンス](/docs/config-reference/)に記載されています。

## 制限

- プロセッサーは Unix ソケットを必要とするため、Windows ではコンポーザーバーにプロセッサーが無く、テキストはそのまま送られます。ke のリリースは macOS と Linux のみビルドされます。
- サブコマンドのヘルプとエラーメッセージはまだ `herdr` と表記されています。`ke` と読み替えてください。
- プロセッサー、コーディネーター、常駐モデルは ke の一部ではありません。上記のプロトコルが契約のすべてです。
